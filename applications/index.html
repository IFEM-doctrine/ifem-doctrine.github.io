Engineering Case Studies

Projects that demonstrate IFEM principles in practice.

These five selected engineering projects are examined through an IFEM lens. Each entry summarizes the methodology relationship, architectural boundary, and available evidence; the full technical record remains in the dedicated project case study.

These case studies cover projects by Soheil Mozaffari and are presented as evidence-led examples of the relationship between engineering practice and IFEM.

ONYX Framework

An in-progress Rust-centric mission-operations architecture spanning local-first synchronization, persistence, observability, client surfaces, transports, and deployment infrastructure.

Developer tooling / metadata processing

Raven Metadata Extractor

A cross-platform desktop and CLI tool that turns image-folder scans into explainable metadata reports across EXIF, XMP, GPS, C2PA, and bounded AI-origin indicators.

Engineering problemCombine fragmented metadata sources without collapsing uncertain indicators into unsupported conclusions.
IFEM lensSource-specific extractors feed a structured evidence model; responsibilities stay separated and indicators remain distinct from proof.
Evidence & statusActive project. Evidence includes repository structure, cross-platform build workflow, and a real interface capture.

Mobile systems / offline communication

Rezvan Mesh

An Android peer-to-peer communication prototype combining Kotlin, Rust, Bluetooth LE, Wi-Fi Direct, and encrypted local storage for off-grid messaging scenarios.

Engineering problemPreserve communication when ordinary network connectivity is unavailable, without assuming a central server.
IFEM lensAndroid radio and UI concerns are separated from the Rust routing, crypto, and session core through an explicit JNI boundary.
Evidence & statusBeta / validation in progress. Evidence includes source organization, Rust tests, Android build workflow, and a documented device-test procedure.

Multimedia systems / mobile product architecture

Watermelon MediaPlayer

A privacy-oriented offline Android media-player architecture built around explicit Kotlin interfaces and modular playback, storage, subtitle, and presentation boundaries.

Engineering problemKeep an offline media product maintainable as playback, storage, subtitle, and RTL-aware interaction concerns grow.
IFEM lensShared contracts define interfaces while dedicated modules own playback, storage, subtitles, and presentation; implementations are composed at the app boundary.
Evidence & statusActive development. Evidence includes module structure, workflow configuration, and design-system artifacts; no public consumer release is claimed here.
